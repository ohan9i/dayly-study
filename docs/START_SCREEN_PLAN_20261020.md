# Dayly 시작 화면 및 플래너 정리 기획안 — 개정 2

작성·수정일: 2026-10-20  
상태: 기획안 — 서비스 코드 및 배포 변경 없음  
참고: [모트모트 데이브레이커 A5 상품 페이지](https://motemote.kr/product/131826928)

## 1. 개정 방향

“실물 플래너를 펼쳐 나의 디지털 플래너로 들어간다”를 중심 경험으로 삼는다.

기존 기획의 창가·책·스탠드 장면을, 정돈된 스튜디오 배경에 플래너 한 권을 배치하는 구성으로 변경한다. 단순히 시작 화면을 위로 밀어내는 대신, 스크롤 진행량에 따라 플래너가 회전하고 표지가 열리며 기존 앱으로 연결된다.

참고 상품 이미지에서 확인한 시각적 특징은 낮은 채도의 청회색 표지, 작은 직사각형 라벨, 보이는 책등과 종이 두께, 밝은 회색 배경, 한쪽으로 뻗는 그림자다. 여기서 형태·색조·여백을 참고해 Dayly 자체 표지와 장면을 만든다. 아래 색상과 회전 수치는 참고 사진의 측정값이 아닌 디자인 제안이다.

## 2. 첫 화면의 인상과 배치

- 배경: 밝은 웜그레이 또는 아이보리의 스튜디오 공간. 바닥과 배경 사이 경계는 거의 보이지 않게 처리한다.
- 오브젝트: 화면 가운데에 세워 놓은 닫힌 A5 비율 플래너 한 권. 정면과 책등이 함께 보이는 사선 구도.
- 표지: 무광 청회색, 작은 Dayly 라벨, 은은한 종이 결. 장식은 표지의 재질과 두께로 표현한다.
- 조명: 우측 위에서 들어오는 넓고 부드러운 빛과 좌측 아래로 떨어지는 그림자.
- 텍스트: 상단의 작은 Dayly 로고, 필요하면 “오늘의 계획” 한 줄. 상품 사진처럼 오브젝트 주변에 넓은 여백을 둔다.
- 조작: 아래쪽의 “스크롤해서 펼치기 ↓”, 별도의 작은 “플래너 바로 열기” 링크.
- 제외: 시작 화면의 스탠드·식물·유리 카드·명언·부유 입자.

| 용도 | 밝은 테마 제안 | 어두운 테마 제안 |
| --- | --- | --- |
| 배경 | 웜그레이 `#F0EFEB` | 차콜 `#202329` |
| 플래너 표지 | 청회색 `#68758D` | 슬레이트 블루 `#4E5C73` |
| 종이 | 아이보리 `#FAF8F2` | 밝은 종이 유지, 조명만 낮춤 |
| 본문 | 짙은 회색 `#2C3035` | 따뜻한 밝은 회색 `#E9E7E2` |

기존 아침·밤 설정은 유지하되, 이번 시각 방향에서는 각각 밝은 스튜디오와 어두운 스튜디오로 해석한다. 플래너 구간에도 같은 배경 계열을 이어 주어 갑자기 다른 사이트로 바뀌는 느낌을 줄인다.

## 3. 추천 스크롤 시나리오

```text
① 닫힌 플래너
   무광 표지 + 작은 라벨 + 부드러운 그림자
             ↓ 스크롤
② 플래너가 천천히 회전
   책등과 종이 두께가 보이고 시점이 위쪽으로 이동
             ↓ 스크롤
③ 표지가 열리고 종이 면이 정면을 향함
   종이 위에 날짜·체크 행의 형태가 나타남
             ↓ 스크롤
④ 종이 면이 커지며 실제 플래너 영역과 연결
   장식 오브젝트는 사라지고 실제 입력·체크 UI가 활성화
```

아래 비율은 전체 웹페이지가 아니라 시작 화면의 전환 구간을 기준으로 한다.

| 진행률 | 화면 연출 | 연결 의도 |
| --- | --- | --- |
| 0–20% | 플래너가 사선 상태에서 천천히 회전. 안내 문구가 사라짐 | 두께와 재질을 보여준다. |
| 20–50% | 약 30–60도 범위의 방향 전환과 함께 표지가 책등을 축으로 열림 | 실물 노트를 여는 행동을 표현한다. |
| 50–75% | 펼쳐진 종이가 정면을 향하며 확대. 날짜와 체크 행의 윤곽 등장 | 종이와 실제 앱 사이에 시각적 공통점을 만든다. |
| 75–100% | 종이 면과 실제 할 일 영역의 위치·색을 맞추며 짧게 교차 전환. 앱 탐색 UI 등장 | 실제 사용 화면으로 이어진다. |

360도 회전보다 부분 회전 후 펼침을 기본안으로 추천한다. 책의 형태를 읽을 시간을 주고 “플래너를 열어 사용한다”는 행동과 연결할 수 있기 때문이다.

대안: 표지 펼침의 품질이 충분하지 않으면 “닫힌 플래너 부분 회전 → 확대 → 종이색 화면으로 전환 → 실제 앱 등장”으로 단순화한다. 시제품에서 비교하되 추천안은 펼침형이다.

## 4. Soda 프롬프트의 적용 범위

| 원본의 요소 | Dayly 적용 |
| --- | --- |
| 중앙의 입체 캔 | 표지·책등·종이 단면이 있는 플래너 |
| 포인터 방향으로 기울기 | 스크롤 시작 전 최대 약 2도의 미세 기울기 |
| 클릭에 따른 720도 회전과 오브젝트 교체 | 스크롤 진행량에 따른 부분 회전·표지 펼침·화면 연결 |
| 강한 배경 색상 변화 | 종이와 스튜디오 색조가 자연스럽게 이어지는 전환 |
| 주변 과일·기포·반발 효과 | 생략. 플래너 한 권의 형태와 그림자에 집중 |
| 스크롤이 없는 단일 HTML | 기존 React 앱 위의 스크롤 연출 구간으로 재구성 |

첫 등장에는 약 600–800ms의 짧은 등장 연출을 사용할 수 있다. 이후 회전과 펼침은 시간에 따라 자동 재생하지 않고 스크롤 위치에 연결한다. 손을 멈추면 오브젝트도 멈추고, 위로 스크롤하면 같은 동작이 역방향으로 진행된다.

Emil 디자인 원칙에 따라 연출은 시작 구간에 집중한다. 플래너의 입력·체크·날짜 이동에는 이 회전 효과를 적용하지 않는다.

## 5. 스크롤과 접근성

- 기본 브라우저 스크롤을 유지한다. 휠·터치 입력을 가로채거나 강제 스냅하지 않는다.
- 시작 구간의 장면은 짧게 고정되는 sticky 방식으로 설계한다. 전체 진입 거리는 약 1.5–2개 화면 높이를 시제품의 출발점으로 삼고 실제 사용감으로 조정한다.
- 마지막 전환에는 실제 앱의 배치와 시작 장면을 맞춘다. 긴 빈 구간이나 두 플래너가 겹쳐 보이는 순간을 만들지 않는다.
- “플래너 바로 열기”는 긴 연출을 건너뛰고 실제 앱 위치로 즉시 이동한다.
- 키보드의 건너뛰기 링크도 같은 목적지를 사용하고, 이동 후 플래너 제목으로 포커스를 전달한다.
- 동작 줄이기 설정에서는 정적인 표지와 일반 스크롤만 제공한다. 불필요한 sticky 구간도 제거한다.
- 모바일은 회전각과 전환 거리를 줄이고 포인터 기울기를 제거한다. 작은 화면에서 표지나 버튼이 잘리지 않게 한다.
- 연출 중인 앱은 조기 클릭·키보드 접근을 받지 않도록 하고, 실제 화면을 드러내는 시점과 조작 가능 시점을 맞춘다.
- 시작 화면이 보이지 않으면 렌더링과 포인터 처리를 멈춘다. 위로 돌아올 때 현재 스크롤 위치에 맞게 복원한다.

## 6. 기존 플래너 정리

기존 기능과 데이터 흐름은 유지하면서, 배경과 보조 장식을 새 시작 화면의 색조에 맞춰 정돈한다.

| Before | After | Why |
| --- | --- | --- |
| 오른쪽 큰 시계·명언 박스 | 박스 제거, 시간은 날짜 옆 작은 텍스트로 이동 | 할 일 목록에 시선 집중 |
| 명언·응원 제목과 부제 | 삭제 또는 “오늘의 계획”으로 정리 | 목적에 필요한 문구만 표시 |
| 책·스탠드 장식 | 제거, 시작 화면의 플래너 오브젝트에 시각적 강조 집중 | 반복 노출되는 장식 줄이기 |
| 창가 풍경과 강한 유리 효과 | 스튜디오와 이어지는 단색 계열 배경 및 종이처럼 차분한 표면 | 시작 화면과 앱의 일관성 확보 |
| 강조된 카드 외곽선·그림자 | 얇은 경계와 낮은 그림자 | 박스보다 본문이 먼저 보이게 함 |
| 오른쪽 테마 선택기 | 기존 상단·설정의 테마 조작으로 통합 | 조작 중복 제거 |

할 일 본문, 체크 상태, 입력 경계, 오류 안내의 대비는 유지한다. “박스를 덜 보이게” 하는 것은 읽는 내용까지 흐리게 만드는 것을 의미하지 않는다.

## 7. 오브젝트 제작 및 구현 구조

사진 한 장을 회전시키면 옆면·뒷면·펼쳐진 내부가 만들어지지 않는다. 추천 연출에는 앞표지·뒤표지·책등·종이 묶음을 별도 요소로 가진 Dayly 오브젝트가 필요하다.

- 기본 제작안: 단순한 3D 책 구조와 자체 표지. 앞표지를 책등 축으로 회전시킬 수 있게 분리한다.
- 구현 후보: Three.js로 오브젝트·조명을 구성하고, GSAP ScrollTrigger로 스크롤 진행과 장면 전환을 연결한다. 버전과 연동 방식은 구현 단계에서 확인한다.
- 가벼운 대안: CSS 3D의 표지·책등·종이 레이어. 각도 변화가 작은 경우 적합하며 실제 그림자와 곡면 표현에는 한계가 있다.
- 오브젝트가 준비되기 전에는 동일 구도의 정적 포스터를 표시한다. 로딩 완료가 플래너 사용의 조건이 되지 않게 한다.
- 장식용 속지는 빈 체크 행 또는 일반적인 줄만 표현한다. 사용자 할 일을 별도 3D 텍스처에 복제하지 않고 마지막에 실제 앱 DOM으로 연결한다.
- 실제 플래너는 한 번만 마운트하고 상태를 유지한다. 시작 화면 진입·이탈 때문에 입력이나 인증 상태를 초기화하지 않는다.

예상 코드 책임:

| 파일·영역 | 책임 |
| --- | --- |
| `WelcomeScreen.tsx` | 시작 레이아웃, 안내, 건너뛰기, 접근성 |
| `PlannerObject.tsx` | 표지·책등·종이 구조와 장면 |
| 스크롤 제어 모듈 | 회전·펼침·전환 진행률, 재진입, 정리 처리 |
| `App.tsx` | 실제 플래너와 연결, 명언·보조 카드 정리 |
| `Atmosphere.tsx` / 스타일 | 테마 공유, 스튜디오 색조, 플래너 표면 정리 |

스크롤 진행률은 매 프레임 React 상태에 저장하지 않는다. 관찰자는 구간 활성 여부를 판단하고, 연속적인 변형은 애니메이션 계층에서 처리한다. 스크롤 중에는 포인터 기울기를 중단해 두 제어가 충돌하지 않게 한다.

## 8. 진입·복원 규칙

- 기본 주소에 새로 접속하면 시작 화면을 보여준다.
- 플래너 진입 후 달력·설정 이동은 시작 연출을 다시 재생하지 않는다.
- 같은 탭의 새로고침·뒤로 가기에서는 사용 중이던 화면과 위치 복원을 우선한다.
- 비밀번호 재설정 등 목적이 있는 링크는 해당 기능으로 바로 연결한다.
- 첫 버전에는 “다시 보지 않기” 설정을 추가하지 않는다. 즉시 건너뛰기는 항상 제공한다.

## 9. 구현 순서 및 완료 조건

1. 청회색 표지·스튜디오 배경·조명·그림자의 정적 장면을 만든다.
2. 회전 → 표지 펼침 → 실제 UI 연결의 스크롤 시제품을 만든다.
3. 플래너의 명언·보조 카드·배경을 정리하고 실제 앱과 연결한다.
4. 테마, 진입 복원, 키보드, 모바일, 동작 줄이기 대응을 완성한다.
5. 기능 및 화면 검증 후 구현 작업의 배포 단계에서 실제 주소를 확인한다.

완료 조건:

- 첫 화면에서 플래너 한 권과 명확한 그림자가 중심으로 보인다.
- 스크롤을 멈추거나 되돌리면 오브젝트도 그 위치에 맞게 반응한다.
- 표지·종이 사이에 빈 면, 관통, 갑작스러운 점프가 없다.
- 종이에서 실제 앱으로 넘어갈 때 위치·색상·크기가 부자연스럽게 튀지 않는다.
- 건너뛰기, 빠른 스크롤, 위로 스크롤, 창 크기 변경에도 플래너에 접근할 수 있다.
- 모델 로딩 실패와 WebGL 불가 환경에서도 정적 화면과 기존 앱을 사용할 수 있다.
- 320px 폭에서도 주요 버튼이 잘리거나 가로 스크롤이 생기지 않는다.
- 키보드 포커스가 가려진 장면이나 앱 요소에 갇히지 않는다.
- 시작 화면 밖에서는 불필요한 렌더링이 중단된다.
- 명언·큰 시계 박스가 없어지고 할 일의 가독성은 유지된다.
- 작성 중 입력, 로그인, 저장, 날짜 탐색, 공유 및 인증 링크가 정상 작동한다.
- 기존 테스트와 새 스크롤 진입 흐름의 브라우저 검증이 통과한다.
