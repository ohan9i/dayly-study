# 공유 체크와 공간 사이의 항목 이동

## 적용 범위

사용자가 선택한 **현재 사람별 공유 공간 사이에서 항목 이동** 방식입니다. 새 Room이나 참여자별 플래너 테이블은 만들지 않습니다. 이동 대상은 로그인한 사람이 접근할 수 있는 기존 공간입니다.

| 동작 | 허용 대상 |
| --- | --- |
| 할 일·세부 항목 체크/해제 | 이메일 확인을 마친 해당 공간 참여자 |
| 제목·날짜·세부 항목 수정/삭제 | 기존 정책 그대로 작성자 또는 공간 소유자 |
| 다른 공간으로 이동 | 원래 공간의 작성자 또는 소유자이며, 대상 공간 참여자 |
| 수행 내용 수정/삭제 | 기존 정책 그대로 기록 작성자 또는 공간 소유자 |

## 서버 적용

기존 스키마와 20261005 파일/공간 migration 설치 후, **`supabase/migrations/20261006_shared_checks_and_moves.sql` 전체를 SQL Editor에서 실행**해야 합니다. 반복 실행할 수 있으며 transaction 중 오류가 발생하면 전체 변경이 취소됩니다. 이전 migration을 다시 적용할 경우 마지막에 이 파일을 재실행합니다. 이 파일을 설치한 뒤 새 홈페이지를 배포합니다. 이전 홈페이지의 전체 항목 저장 방식은 동시 체크를 덮어쓸 수 있으므로 최신 홈페이지로 새로고침해야 합니다.

## 저장과 동시 변경

- `set_task_completion`: 데이터베이스 행을 `FOR UPDATE`로 잠근 뒤 요청한 체크만 수정합니다. 현재 서버 상태를 반전하는 대신 요청한 true/false를 저장해 같은 오래된 상태에서 두 사람이 체크한 요청이 서로 취소되지 않습니다.
- 완료 상태와 `completedBy`, `completedAt`은 기존 `tasks.details` JSON에 함께 저장합니다. 새로운 완료 변경의 작성자·시각은 서버가 결정합니다. 해제하면 현재 완료의 작성자·시각은 비웁니다. 별도 전체 활동 이력 UI는 추가하지 않았습니다.
- `update_task_content`: 같은 행 잠금 아래 안정적인 세부 항목 ID로 최신 체크를 합칩니다. 오래 열어 둔 편집창의 체크 상태로 다른 사람의 변경을 덮어쓰지 않습니다. 새 세부 항목은 미완료로 시작합니다.
- 직접 `details`/`detail_items` 수정과 완료 테이블 삽입/삭제 권한은 제거했습니다. 체크용 함수는 제목·날짜·작성자·공간을 변경할 수 없습니다.
- `revision`은 항목 변경 때마다 증가합니다. 저장 중 시작된 이전 조회는 클라이언트의 generation 검사로 버립니다. 저장 실패 시 낙관적 상태를 복구하고 서버를 다시 읽습니다.

## 동기화

`workspace_activity`에는 공간별 변경 번호만 기록합니다. 이 테이블의 읽기 권한도 해당 공간 참여자로 제한합니다. 항목·기록·첨부가 바뀌면 Realtime 알림을 받고 화면을 배경에서 갱신합니다. Realtime 연결이 끊기면 5초 간격으로 변경 번호를 확인하며, 변경이 있을 때만 기록을 다시 읽습니다. 알림은 원래 공간과 이동 대상 공간 모두에 전달됩니다. 공간 접근 권한이 사라지면 캐시를 갱신하고 접근 가능한 공간을 다시 선택합니다.

체크 후 서버의 결과를 즉시 화면에 반영합니다. 배경 갱신은 입력창을 다시 만들거나 loading 배너를 추가하지 않습니다. 편집 중인 텍스트·한글 조합·파일 선택을 유지하며, 체크 상태만 세부 항목 ID별로 갱신합니다.

## 이동

상세보기 하단 **다른 플래너로 이동**에서 대상 공간을 고릅니다. 내 공간을 먼저 표시하고 기본 선택합니다. 저장하지 않은 변경이나 첨부는 먼저 저장합니다. 성공하면 작은 알림과 함께 대상 공간으로 전환합니다.

`move_task`는 체크/편집과 동일한 행을 잠그고 `workspace_id`만 바꿉니다. 외래키의 `ON UPDATE CASCADE`로 완료·기록·첨부의 공간도 같은 transaction 안에서 이동합니다. ID, 작성자, 날짜, 생성 시각, 세부 항목 ID, 기록 본문, 파일 관계는 유지합니다. 공간 이동만으로 기록의 수정 시각이 바뀌지 않습니다. 제목 기준 기존 정렬을 유지합니다.

파일 원본은 복사하거나 지우지 않습니다. `storage_workspace_id`가 원래 저장 경로를 보존하고, Storage 정책은 첨부의 **현재** 공간 접근 권한을 검사합니다. 새 공간에 접근할 수 없는 원래 소유자는 새 미리보기 링크나 파일을 읽을 수 없습니다. 이전에 발급한 미리보기 링크의 기존 2분 유효기간은 그대로입니다.

진행률·달력·학습 흐름은 기존 공통 계산 함수를 그대로 사용합니다. 원래 공간에서 항목을 제거하고 대상 공간 데이터를 불러오면 각 공간의 계산이 즉시 갱신됩니다.

## 검증 범위

PGlite의 실제 PostgreSQL 엔진에 migration을 두 번 설치해 반복 실행, 참여자/작성자/소유자/외부인/미인증 계정 권한, 오래된 체크 요청·편집 저장, ID·완료·기록 시각·파일 경로 보존, 이동 후 Storage 접근 차단을 검사합니다. 브라우저 검증은 실제 Supabase SDK와 테스트 API를 사용합니다. 실제 사용자 기록을 생성하거나 이동하지 않습니다.

2026-10-06 검증: 단위·SQL 34개 통과, 브라우저 34개 검증 완료(전체 검사 후 수정한 항목을 재검사), production build 성공. 브라우저의 소수점 픽셀 계산 오차는 44px 버튼 너비의 근사 비교로 처리했습니다. 새 공간의 변경 알림 행이 아직 없을 때 초안을 불필요하게 다시 읽지 않는 것, 승인 해제 시 공유 캐시 제거, 수동 새로고침 도중 다른 사람의 변경이 도착해도 loading 상태가 해제되는 것도 확인했습니다. 실제 Supabase에 세 함수가 설치됐고 비로그인 호출이 거부되는 것을 확인했습니다.
