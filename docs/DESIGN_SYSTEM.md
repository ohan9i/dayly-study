# Dayly 디자인 시스템

2026-10-05 시각 개선 기록입니다. 콘셉트는 **여름 아침 창가에 놓인, 물성이 느껴지는 조용한 공부 플래너**입니다.

## 주요 결정

- 창가·바다 배경과 파란색 계열을 그대로 사용합니다. 배경 파일을 편집하거나 외부 폰트를 추가하지 않았습니다.
- 사이드바는 120px에서 96px로 줄였습니다. 선택된 메뉴 뒤의 밝은 표면이 이동하고, 모든 메뉴 아이콘은 선형으로 통일했습니다.
- 홈 카드와 제목의 간격을 조정하고, 높이 820px 이하의 화면에서는 보조 인사 문구를 숨깁니다. 1366×768에서도 카드 아래의 책상과 열린 책이 보입니다.
- 카드는 흰색 종이의 편안함과 미세한 유리 반사를 함께 표현합니다. 배경을 선명하게 드러내기보다 색과 빛만 받아들이게 했습니다.
- 시계는 작게 조정하고 창틀과 겹치지 않게 왼쪽으로 옮겼습니다. 문구는 청회색으로 표시하고 장식 따옴표·영문 표어를 덜어냈습니다.
- 로그인 전 예시 안내와 로그인 동작을 카드 하단 한 곳에 모았습니다. 저장 상태는 로그인 후에 표시합니다.
- 달력의 일반 날짜 칸은 투명하게 두고 오늘·선택한 날짜·할 일이 있는 날짜만 구분합니다.
- 통계 요약은 세 개의 카드 대신 하나의 띠로 묶었습니다. 기록이 없는 날짜의 반복적인 `0/0`을 숨기고, 한 주가 비어 있으면 설명이 있는 빈 화면을 표시합니다. 통계 계산은 기존 함수를 사용합니다.
- 설정·계정·검색·할 일 상세·수행 내용·파일 미리보기에 같은 글자와 폼 규칙을 적용했습니다.

## 디자인 토큰

실제 정의는 `src/styles.css` 맨 위의 `:root`에 있습니다.

| 역할        | 변수                                                                            | 값 또는 용도                                 |
| ----------- | ------------------------------------------------------------------------------- | -------------------------------------------- |
| 하늘색 계열 | `--sky-50` ~ `--sky-600`                                                        | 배경색, 선택 상태, 진행률, 주요 동작         |
| 본문        | `--text`                                                                        | `#243f52`                                    |
| 보조 글자   | `--text-secondary`, `--text-muted`, `--text-faint`                              | 위계에 맞춘 청회색                           |
| 구분선      | `--line`                                                                        | 약한 청회색 12%                              |
| 카드 표면   | `--glass-bg`                                                                    | 흰색·하늘색 alpha 0.79 → 0.70                |
| 카드 경계   | `--glass-border`                                                                | 흰색 alpha 0.64                              |
| 블러        | `--glass-blur`                                                                  | 24px                                         |
| 그림자      | `--shadow-soft`, `--shadow-dialog`                                              | 넓고 약한 그림자와 얇은 안쪽 반사            |
| 곡률        | `--radius-lg`, `--radius-card`, `--radius-md`, `--radius-sm`                    | 26 / 22 / 14 / 10px                          |
| 간격        | `--space-1` ~ `--space-8`                                                       | 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px        |
| 글자        | `--type-meta`, `--type-support`, `--type-body`, `--type-section`, `--type-hero` | 12 / 13 / 15 / 18 / 28~34px                  |
| 레이아웃    | `--sidebar-width`, `--content-width`                                            | 96px, 기본 1120px                            |
| 움직임      | `--ease`, `--duration`                                                          | `cubic-bezier(0.22, 1, 0.36, 1)`, 기본 220ms |
| 입력 초점   | `--focus-ring`                                                                  | 파란색 경계와 넓고 약한 링                   |

주요 버튼의 흰색 글자는 더 진한 `--sky-600` 위에 표시합니다. 숫자는 Pretendard의 고정 폭 숫자를 사용합니다. 세부 항목은 제목 아래 13px 보조 글씨로 표시하고 입력 행은 기존 반투명 표면과 초점 표시를 따릅니다. 과목 태그와 예정 시간은 세부 항목 도입 후 표시하지 않습니다.

## 화면 크기별 규칙

| 조건               | 적용                                                                   |
| ------------------ | ---------------------------------------------------------------------- |
| 1600px 이상        | 콘텐츠 너비 1220px, 카드 여백과 행 간격 확대, 시계 70px                |
| PC 높이 820px 이하 | 위쪽 여백·행 높이 조정, 홈 보조 문구 숨김                              |
| 1200px 이하        | 중앙과 시계 사이의 간격 축소                                           |
| 1000px 이하        | 시계 영역을 숨기고 한 열로 표시                                        |
| 700px 이하         | 하단 내비게이션, 별도 모바일 로고, 제목 아래 세부 항목, 16px 입력 글자 |
| 380px 이하         | 날짜 입력을 한 열로 배치, 진행률 막대를 숨기고 숫자로 표시             |

모바일 날짜는 17px, 메타데이터는 최소 12px입니다. 주요 메뉴·상단 동작·추가·체크·세부 항목 삭제 버튼은 높이 44px 이상의 터치 영역을 갖습니다. 달력 칸에서는 완료 수치를 표시하고 전체 설명은 접근성 이름에 남깁니다. 긴 제목과 세부 항목은 자연스럽게 줄바꿈하고 긴 파일명은 필요한 곳에서 말줄임하되 상세 화면에는 원문을 유지합니다.

## 인터랙션

- 완료 체크: 체크 표시의 짧은 진입 효과, 글자색·취소선·행 표면의 상태 변화.
- 진행률: 420ms 너비 전환과 완료 숫자의 짧은 변화. 화면 읽기 도구에 완료 수치를 안내합니다.
- 메뉴: 선택된 표면의 320ms 이동.
- 화면: 7px 이동과 260ms 페이드.
- 팝업: 6px 이동·작은 크기 변화와 240ms 페이드.
- 버튼: 밝기와 1px 높이 변화. 실제 누를 수 있는 요소에 반응을 적용합니다.
- `prefers-reduced-motion: reduce`에서는 애니메이션과 전환을 끕니다.

페이지 진입 애니메이션은 종료 후 transform/opacity를 남기지 않습니다. 부모의 합성 상태가 카드의 backdrop blur를 막지 않도록 하기 위한 규칙입니다. 블러를 지원하지 않는 환경에는 불투명도를 높인 카드 표면을 제공합니다.

## 검증

- 1920×1080, 1440×900, 1366×768, 768×1024, 390×844, 360×800, 320×740에서 홈·달력·통계·설정을 렌더링하고 캡처했습니다.
- 모든 화면에서 가로 넘침과 12px 미만의 본문·메타데이터가 없는 것을 검사했습니다.
- 계정·검색·할 일 상세, 로그인한 빈 화면, 긴 제목과 과목명, 첨부 파일과 수행 내용도 확인했습니다.
- 320px 상세 창의 긴 파일명으로 발견된 가로 넘침은 파일 목록의 grid 열을 `minmax(0, 1fr)`로 제한하여 해결했습니다.
- 기존 단위·권한 테스트 19개 통과. 첨부 창의 넘침 수정 후 기존 브라우저 시나리오 10개를 전체 실행하여 모두 통과했습니다.
- 움직임 줄이기 설정에서 화면 애니메이션이 비활성화되는 것을 확인했습니다.

브라우저 검증은 Chromium과 테스트용 Supabase API 응답을 사용합니다. 실제 사용자 데이터와 이메일 발송을 변경하지 않았습니다. 위 검증 결과는 초기 V2 디자인 개선 시점의 기록입니다. 이후 입력 구조 변경과 저장 호환 처리는 [세부 항목 구현 기록](TASK_DETAIL_ITEMS.md)에 정리했습니다. 사이트 배포는 기존 `.github/workflows/deploy.yml`의 GitHub Pages 워크플로를 사용합니다.

## 추가로 확인할 만한 환경

1. 실제 iPhone Safari에서 날짜 선택기와 화면 키보드가 열린 상태의 팝업.
2. 실제 계정에서 이미지·PDF가 많이 첨부된 상세 화면.
3. Windows 배율 125~150%와 모바일의 큰 글자 설정.
