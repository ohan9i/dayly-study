# 할 일의 세부 항목

## 데이터와 저장

앱과 JSON 백업은 `details: string[]`를 사용합니다. 제목과 날짜는 메인 할 일에 속합니다. 이후 추가한 체크 상태와 안정적인 항목 ID는 `detailChecks`에 같은 순서로 보관합니다. `subject`, `time`은 새 할 일에서 요구하거나 전송하지 않습니다. 기존 행에 있는 값은 보존하지만 UI·검색·정렬·통계에서는 참조하지 않습니다. 백업 형식은 v2이며 localStorage 키는 기존 `dayly.planner.v1`을 유지합니다.

```ts
{
  title: "수학 공부",
  date: "2026-10-05",
  details: ["순열 문제 10개 풀기", "조건부확률 복습", "오답노트 정리"]
}
```

- 로그인 후에는 Supabase에 저장합니다. 로그인 전의 localStorage 기록은 기존 정책대로 읽기 전용입니다.
- 현재는 기존 `details text`에 `dayly:progress:v1:` 접두사와 항목 ID·텍스트·완료 상태를 담은 JSON을 저장합니다. `detail_items text[]` 열이 있으면 텍스트 배열도 함께 저장합니다. 한 행의 쓰기로 체크와 부모 완료 상태를 일관되게 저장합니다.
- 이전 `dayly:details:v2:` JSON 배열과 일반 문자열 메모도 계속 읽습니다. 줄바꿈으로 새 항목을 연결하지 않습니다. 저장 호환성과 계산 방식은 [진행률 구현 기록](TASK_PROGRESS.md)에 설명합니다.
- 빈 공간에서는 배열 열의 존재를 쓰기 요청으로 확인합니다. 해당 열이 없다는 오류에만 호환 저장을 한 번 시도합니다. 권한·통신 오류에는 재시도하지 않습니다. 이미 배열 열을 읽은 경우에는 텍스트로 대체하지 않아 저장된 배열과 충돌하지 않습니다. [PostgREST 오류 코드](https://docs.postgrest.org/en/stable/references/errors.html)
- 항목 개수 제한은 없습니다. 기존 DB의 10,000자 저장 용량은 유지하며, 초과 시 내용을 줄이라는 안내를 표시합니다.

## 기존 기록 호환

v1 백업, 기존 `details: string`, `memo: string`을 읽습니다. 기존 메모 한 줄은 세부 항목 하나로 변환하며 여러 줄 메모는 원래 순서대로 나눕니다. 앞뒤 공백과 빈 줄만 제외합니다. 할 일 ID, 날짜, 완료 상태와 첨부·수행 내용 연결은 유지합니다. 일반 JSON처럼 보이는 메모는 그대로 살리고, 전용 접두사가 있을 때만 JSON 배열로 해석합니다.

배열 열의 `null`은 기존 메모를 읽으라는 의미이고, `[]`는 사용자가 세부 항목을 모두 삭제했다는 의미입니다. 따라서 삭제 후 예전 메모가 되살아나지 않습니다. 기존 localStorage 원본은 읽는 과정에서 덮어쓰지 않습니다.

실제 DB에 배열 열을 추가하는 선택적 업그레이드는 `supabase/migrations/20261005_task_detail_items.sql`입니다. 기존 행을 수정하거나 열을 삭제하지 않으며 반복 실행할 수 있습니다. SQL을 적용하지 않은 기존 DB에서도 호환 저장으로 동작합니다. 관리 연결이 없는 환경에서는 SQL 파일을 제공하고 기존 저장 형식을 사용합니다.

## 화면과 키보드

- 추가·수정에서 동일한 `DetailItemsEditor`를 사용합니다. 독립된 한 줄 input과 조용한 `×` 버튼을 사용합니다.
- `한 줄 추가`는 마지막에 빈 줄을 추가하고 초점을 옮깁니다.
- 내용이 있는 input의 Enter는 바로 아래에 새 줄을 추가합니다. 빈 줄의 Enter는 저장하거나 줄을 추가하지 않습니다.
- 한글 composition 이벤트, `isComposing`, keyCode 229를 검사합니다.
- 빈 줄의 Backspace는 이전 입력칸의 끝으로 이동하며 어떤 줄도 삭제하지 않습니다.
- `×`는 해당 줄만 삭제합니다. 마지막 줄까지 삭제할 수 있고 제목만 저장할 수 있습니다.
- 항목을 추가·삭제해도 안정적인 ID로 input을 유지해 기존 줄의 입력과 커서가 초기화되지 않습니다.
- 홈에는 제목 아래 작은 글씨의 목록과 독립 체크박스를 표시합니다. 모든 세부 항목이 완료되면 부모 할 일도 완료됩니다. 달력·주간 통계도 세부 항목 단위 진행률을 사용합니다. 각 할 일의 얇은 바와 그날의 작은 원은 같은 계산 함수를 사용합니다.
- 과목별 통계 패널은 제거하고 기존 완료 수·달성률·실천한 날과 7일 차트는 유지합니다.
- Dayly V2의 반투명 입력 표면, 모서리, 초점 표시와 여백을 사용합니다. 삭제 버튼은 44px 터치 영역이며 input 옆에 별도 배치합니다.

## 주요 파일

- `src/domain.ts`: 타입, v1/v2 파싱, 기존 메모 변환, 배열 정리와 직렬화
- `src/planner.ts`: Supabase 읽기·쓰기와 DB 호환 저장
- `src/DetailItemsEditor.tsx`: 목록 입력, 키보드와 초점
- `src/TaskDetail.tsx`: 추가·수정 화면, 저장 데이터
- `src/App.tsx`, `src/styles.css`: 홈 목록, 검색·통계, 반응형 디자인
- `supabase/schema.sql`, 새 migration: 선택적 PostgreSQL 배열 열
- `tests/domain.test.ts`, `tests/detail-items-migration.test.ts`, `tests/e2e/*`: 호환성·DB·브라우저 검증

## 검증 범위

입력 구조 변경 당시 결과: `npm run build` 성공, 단위·SQL 검사 22개 통과, 브라우저 검사 17개 통과. PC와 390px·360px의 실제 렌더링 캡처도 확인했습니다. 이후 진행률 기능 검증은 [진행률 구현 기록](TASK_PROGRESS.md)을 참고하세요.

단위·SQL 검증은 실제 PostgreSQL 엔진(PGlite)에 스키마와 migration을 실행합니다. 브라우저 검증은 Chromium에서 실제 Supabase SDK와 테스트 API를 사용하므로 사용자의 계정과 기록을 바꾸지 않습니다.

요청한 제목만 생성, 1개·여러 개 생성, 중간·마지막·전체 항목 삭제, Enter, 빈 항목 제거, 수정과 순서 보존, 기존 memo와 문자열 메모, 새로고침, 모바일 390px·360px을 검사합니다. 기존 완료·삭제·검색·달력·통계, 로그인 권한, 첨부·수행 내용과 입력 중 초점 유지도 함께 검사합니다.

모바일에서는 12줄을 추가하며 입력칸과 삭제 버튼의 실제 위치, 입력 너비, 가로 넘침과 초점 이동을 검사합니다. 한글 조합 검증은 composition 이벤트와 키 입력을 사용하며 OS별 실제 모바일 키보드는 포함하지 않습니다.
