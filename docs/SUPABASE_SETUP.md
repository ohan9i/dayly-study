# 로그인과 승인된 작성자 연결하기

현재 홈페이지는 Supabase 계정으로 로그인한 뒤 편집합니다. 연결 정보와 테이블을 설정했으며, 아래는 설정을 다시 확인하거나 새 프로젝트로 옮길 때의 안내입니다.

## 1. 새 Supabase 프로젝트 만들기

[Supabase 대시보드](https://supabase.com/dashboard)에서 새 프로젝트를 만듭니다. 데이터베이스 비밀번호는 본인이 보관합니다. 웹사이트 코드나 채팅에 넣을 필요가 없습니다.

이 홈페이지는 새 프로젝트에서 사용하는 것을 기준으로 했습니다. 기존 프로젝트에 같은 이름의 테이블이 있으면 먼저 이름 충돌을 확인하세요.

## 2. 테이블과 권한 만들기

프로젝트의 **SQL Editor**에서 `supabase/schema.sql`의 전체 내용을 붙여 넣고 실행합니다. 한 번만 실행합니다. 실행은 하나의 트랜잭션으로 처리됩니다.

생성되는 데이터는 다음과 같습니다.

- `workspaces`: 본인의 공유 공간과 소유자
- `workspace_members`: 작성자로 승인한 이메일
- `tasks`: 날짜별 할 일과 직접 입력한 과목명(선택, 최대 40자)
- `task_completions`: 완료 체크. 관리자만 추가, 삭제할 수 있습니다.

이전에 v1 스키마를 설치한 프로젝트라면 전체 스키마를 다시 실행하지 말고 `supabase/migrations/20261005_custom_subjects.sql`을 실행합니다. 기존 할 일과 완료 체크를 유지하면서 과목 직접 입력을 허용합니다. 이전 `study_logs` 테이블은 홈페이지에서 읽거나 표시하지 않습니다.

그다음 새 프로젝트와 기존 프로젝트 모두 **`supabase/migrations/20261005_task_files_and_personal_spaces.sql`** 전체 내용을 SQL Editor에서 실행합니다. 이미 실행했다면 추가 작업은 없습니다. 이 파일은 다시 실행해도 기존 데이터를 유지합니다.

- `ensure_personal_workspace()`: 이메일 확인 후 로그인한 사람의 내 공간을 자동으로 준비합니다. 이미 본인 소유의 공간이 있으면 그것을 사용합니다.
- `task_notes`: 각 할 일에 남기는 수행 내용과 작성자, 작성 시각
- `task_attachments`: 파일 이름, 크기, 작성자와 저장 경로. 파일 원본은 Storage에 저장합니다.
- `task-files`: 비공개 Storage 버킷. PDF, JPG, PNG, WebP만 허용하며 파일당 10MB 제한을 적용합니다.

파일 접근 권한은 현재 공간의 승인 여부를 검사합니다. 사진과 PDF 미리보기에는 2분간 유효한 링크를 사용합니다. 권한 해제 후 새 링크 발급과 내려받기는 거부되지만, 이미 발급한 링크는 만료 시점까지 사용할 수 있습니다. [Supabase Storage 권한 안내](https://supabase.com/docs/guides/storage/security/access-control)

테이블의 Row Level Security(RLS)는 누가 어떤 기록을 볼 수 있고 바꿀 수 있는지를 데이터베이스에서 검사합니다. 승인된 이메일이어도 인증되지 않은 계정은 공유 기록에 접근할 수 없습니다. [Supabase RLS 공식 문서](https://supabase.com/docs/guides/database/postgres/row-level-security)

## 3. 이메일 로그인 설정

**Authentication → Providers**에서 Email 로그인을 활성화하고 이메일 확인을 유지합니다. 이 홈페이지는 이메일과 비밀번호로 로그인합니다. 회원가입에서 비밀번호를 설정하고 가입 확인 메일의 링크를 눌러야 사용할 수 있습니다. 비밀번호의 최소 길이는 8자 이상으로 설정하세요. 계정이 만들어졌다는 사실만으로 다른 사람의 공간에 접근할 수는 없습니다.

**Authentication → URL Configuration**에서 아래 주소를 등록합니다.

- Site URL: 배포된 홈페이지의 전체 주소
- Redirect URLs: 배포된 홈페이지의 전체 주소와 로컬 테스트용 `http://127.0.0.1:5173/`, `http://127.0.0.1:4173/`

GitHub Pages 주소가 `https://ohan9i.github.io/dayly-study/`라면 끝의 `/`까지 포함해 등록합니다. 가입 확인이나 비밀번호 재설정 메일의 링크가 이 주소로 돌아옵니다.

Supabase 기본 이메일 전송은 프로젝트 설정과 전송 제한에 영향을 받을 수 있습니다. 여러 사람이 계속 사용할 때는 프로젝트의 이메일 전송 설정(SMTP)을 확인하세요. [비밀번호 로그인 안내](https://supabase.com/docs/reference/javascript/auth-signinwithpassword), [비밀번호 재설정 안내](https://supabase.com/docs/reference/javascript/auth-resetpasswordforemail)

## 4. 홈페이지에 공개용 연결 정보 넣기

Supabase의 프로젝트 설정에서 **Project URL**과 **publishable key**를 복사합니다. `sb_secret_...` 키나 `service_role` 키는 사용하지 않습니다. 공개용 키는 사용자를 인증하는 비밀번호가 아니며, 데이터 권한은 로그인과 RLS가 결정합니다. [공개용 키 안내](https://supabase.com/docs/guides/database/secure-data)

내 컴퓨터에서는 `.env.example`을 `.env.local`로 복사한 뒤 다음 값을 넣습니다.

```text
VITE_SUPABASE_URL=https://프로젝트주소.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_공개용키
```

개발 서버를 종료하고 `npm run dev`로 다시 실행합니다. `.env.local`은 Git에서 제외되어 있습니다.

GitHub Pages에서는 저장소의 **Settings → Secrets and variables → Actions → Variables**에 위 이름의 Repository variables 두 개를 추가합니다. 그다음 **Actions → Deploy Dayly to GitHub Pages → Run workflow**로 다시 배포합니다. 이 값들은 빌드된 브라우저 코드에서 공개됩니다. 반드시 publishable key만 넣으세요.

## 5. 내 공간과 승인받은 공간

홈페이지에서 오른쪽 위 계정 버튼 → **회원가입**에서 본인의 이메일과 비밀번호를 입력합니다. 가입 확인 메일의 링크를 누르고 **로그인**에서 이메일과 비밀번호로 로그인합니다. 첫 로그인에 **내 공간이 자동으로 생성**되며 본인이 관리자가 됩니다.

홈의 공간 선택 목록과 **설정 → 계정과 저장**에서 **내 공간**과 **승인받은 공간**을 구분합니다. 내 공간은 본인이 소유하고, 승인받은 공간은 다른 관리자가 허락한 곳입니다. 처음에는 내 공간을 열며, 그다음에는 계정별로 마지막에 선택한 공간을 기억합니다. 내 공간을 공유하는 경우에는 설정의 **내 공간 이름**을 알아보기 쉬운 이름으로 바꿔 주세요.

이전에 브라우저에 작성한 개인 기록은 공유 공간으로 자동 이동하지 않습니다. 로그인 전에 백업 파일을 내려받을 수 있습니다. 로그아웃하면 이 브라우저의 이전 개인 기록 또는 예시 일정을 조회하며, 편집은 잠깁니다.

## 6. 작성자 승인하기

관리자가 **설정 → 함께 쓰는 사람**에서 허락할 사람의 이메일을 입력하고 **작성자 승인**을 누릅니다. 홈페이지 주소를 해당 사람에게 직접 전달합니다.

승인 동작 자체가 초대 메일을 보내지는 않습니다. 승인된 사람은 홈페이지에서 같은 이메일로 회원가입하고 이메일 확인 후 비밀번호로 로그인합니다. 이메일을 바꾸면 그 이메일을 다시 승인해야 합니다.

상대방은 로그인한 다음 홈의 공간 선택 목록에서 **승인받은 공간** 아래에 있는 관리자 공간을 선택합니다. 본인의 내 공간에 자동으로 합쳐지지 않습니다.

작성자는 할 일을 보고 추가하고, 본인이 작성한 항목을 수정하거나 삭제할 수 있습니다. 다른 사람의 할 일 수정과 완료 체크는 할 수 없습니다. 수행 내용과 파일은 함께 남길 수 있으며 본인이 남긴 내용을 관리합니다. 관리자는 전체 항목을 관리하고 완료 체크를 합니다.

권한을 해제하면 이후의 데이터베이스 요청이 즉시 제한됩니다. 이미 화면에 표시되거나 내려받은 내용을 회수할 수는 없습니다. 이전 작성 기록은 유지됩니다. 로그인, 공간 선택, 저장 완료 또는 상단 **공유 기록 새로고침** 버튼을 누를 때 공간 목록과 기록을 확인합니다. 글을 쓰는 중 입력이 끊기지 않도록 주기적인 갱신과 다른 창에서 돌아올 때의 자동 갱신은 하지 않습니다. 로그인 세션은 계속 자동으로 유지됩니다.

승인받은 공간이 보이지 않으면 계정 화면의 로그인 이메일을 먼저 확인하세요. 관리자가 입력한 이메일과 정확히 같은 계정으로 이메일 확인을 마쳐야 합니다. 상단 새로고침 후에도 보이지 않으면 관리자의 승인 목록과 상대방 계정 화면을 함께 확인합니다.

## 파일과 수행 내용 사용하기

할 일을 추가하거나 제목을 눌러 상세 창을 엽니다. 메모 아래 **파일 첨부**에서 한 번에 5개까지 고릅니다. **할 일 저장**을 눌러야 파일이 올라갑니다. 공유 공간의 다른 사람이 만든 할 일에도 자료를 첨부할 수 있으며, 이 경우 **파일 올리기**를 누릅니다.

저장한 할 일의 상세 창 아래에서 **수행 내용 남기기**를 펼칩니다. 짧은 글과 풀이 사진, PDF를 남기고 **수행 내용 저장**을 누릅니다. 파일만 남겨도 됩니다. 별도의 공부 기록 페이지는 추가하지 않았습니다.

업로드에 실패하면 저장한 글과 파일을 구분해 안내합니다. 성공한 파일은 유지하고 실패한 선택 파일은 창에 남겨 다시 저장할 수 있습니다. 업로드 도중 창을 닫았거나 연결이 끊긴 경우, `업로드 미완료` 파일을 삭제하고 다시 첨부해 주세요. 파일 또는 수행 내용 삭제와 할 일 전체 삭제는 Storage 원본을 먼저 지운 다음 데이터 목록을 지웁니다. 데이터베이스에도 원본이 남아 있는 상태의 삭제를 막는 검사를 두었습니다.

JSON 백업에는 할 일, 수행 내용과 파일 목록이 들어갑니다. 파일 원본은 각 카드의 **내려받기**로 따로 보관합니다. 미리보기 링크는 백업에 포함하지 않습니다.

## 7. 연결 후 확인할 것

1. 관리자 계정으로 할 일을 추가하고 완료 체크한 뒤 새로고침합니다.
2. 별도의 브라우저에서 승인한 작성자로 로그인해 같은 기록이 보이는지 확인합니다.
3. 작성자가 직접 입력한 과목명으로 자신의 할 일을 추가하고 수정할 수 있는지 확인합니다.
4. 작성자가 완료 체크와 다른 사람의 기록 수정을 할 수 없는지 확인합니다.
5. 미승인 이메일로 로그인해 관리자의 공간이 보이지 않는지 확인합니다.
6. 관리자가 작성자의 권한을 해제한 뒤, 작성자가 공유 기록을 새로 읽거나 수정할 수 없는지 확인합니다.

예시 일정과 개인 모드 백업은 공유 데이터베이스에 자동으로 올라가지 않습니다.
