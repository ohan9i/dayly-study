# 세부 항목 체크와 진행률

## 최소 변경

기존 페이지 구성, 카드, 색상, 글꼴과 여백을 유지했습니다. 홈 목록과 기존 상세 입력 행에 작은 체크박스를 붙이고, 목록 아래 4px 진행 바와 작은 `완료/전체` 숫자를 추가했습니다. 날짜 영역의 기존 진행 표시 자리에 44px 원을 배치했습니다. 기존 CSS 변수와 220ms 전환을 사용하며 새 대형 섹션이나 색상을 추가하지 않았습니다.

## 상태와 계산

```ts
{
  details: ['문제 풀기', '오답 정리'],
  detailChecks: [
    { id: 'stable-id-1', completed: true },
    { id: 'stable-id-2', completed: false }
  ],
  completed: false
}
```

- 세부 항목 완료 수 / 전체 수로 진행률을 계산합니다. 같은 내용의 항목도 ID로 독립 처리합니다.
- 모든 세부 항목 완료 시 부모도 완료입니다. 하나를 해제하면 부모 완료도 해제합니다. 부모 체크는 모든 세부 항목을 함께 체크/해제합니다.
- 그날의 원은 모든 세부 항목을 합산하며, 세부 항목 없는 할 일은 기존 완료 체크를 1개로 계산합니다. 다른 날짜 선택 시 해당 날짜의 진행률을 표시합니다. 아무 할 일도 없으면 0%입니다.
- 추가·삭제·빈 줄 제외 시 텍스트와 체크 상태를 함께 이동하여 순서와 상태를 보존합니다. 마지막 세부 항목 삭제 후에는 부모 완료 상태를 단일 할 일에 유지합니다.
- 저장된 항목의 체크는 상세 화면에서도 즉시 저장됩니다. 작성 중인 새 항목은 폼 저장 시 저장되며, 기존 항목 체크 시 아직 저장하지 않은 텍스트 수정은 건드리지 않습니다.
- 화면을 먼저 갱신하고 저장 실패 시 복구합니다. 저장 중 중복 입력을 막습니다. 실제 100% 완료 전에 반올림으로 100%가 표시되지 않도록 최대 99%로 표시합니다.
- 체크 저장 성공 후에는 전체 데이터를 다시 불러오지 않습니다. 완료 상태와 진행률만 갱신하며, 상단 로딩 문구로 카드와 스크롤 위치가 움직이지 않습니다. 저장 실패 시에는 기존 상태를 복구하고 화면 로딩 표시 없이 서버 상태를 확인합니다. 수동 새로고침과 다른 저장 기능의 동기화는 유지합니다.

## 저장과 기존 데이터

Supabase의 기존 `tasks.details text` 열에 `dayly:progress:v1:` + `{ items: [{ id, text, completed }], completed }` JSON을 저장합니다. 선택적 `detail_items text[]` 열이 있으면 같은 쓰기에서 텍스트 배열도 저장합니다. 새 테이블이나 필수 migration은 없습니다. 기존 10,000자 제한을 유지합니다.

기존 일반 메모, `memo`, 이전 JSON 배열, native text 배열과 localStorage v1/v2 백업을 계속 읽습니다. ID가 없으면 할 일 ID와 원래 위치로 안정적인 ID를 만듭니다. 기존 미완료 할 일은 세부 항목을 미완료로, 기존 완료 할 일은 모두 완료로 읽어 기존 완료 기록을 보존합니다. 읽기 과정에서 localStorage 원본을 덮어쓰거나 데이터를 초기화하지 않습니다.

이전 기록의 부모 완료는 기존 `task_completions` 테이블에서 읽습니다. 새 진행률 JSON이 있는 기록은 그 행의 체크/완료 상태를 기준으로 `completedTaskIds`를 계산합니다. 두 API 요청으로 부모와 자식을 따로 저장하지 않아 중간 불일치를 피합니다. 세부 항목 없는 이전 기록의 완료 체크는 기존 테이블을 계속 사용합니다. 달력과 주간 통계에는 계산한 부모 완료를 전달합니다.

## 파일

- `src/domain.ts`: ID·체크 타입, 호환 읽기, 직렬화, 진행률과 부모 완료 계산
- `src/planner.ts`: 기존 Supabase 저장, 즉시 갱신과 실패 복구
- `src/DetailItemsEditor.tsx`, `src/TaskDetail.tsx`: 기존 입력 행의 체크와 수정 상태 유지
- `src/TaskProgress.tsx`, `src/App.tsx`, `src/styles.css`: 작은 바와 원, 홈 체크
- `tests/progress.test.ts`, `tests/e2e/progress.spec.ts`: 상태·호환·브라우저 검증

## 검증

`npm run build` 성공, 단위·SQL 검사 29개와 브라우저 검사 25개 모두 통과했습니다. 브라우저 검증은 Chromium과 테스트용 Supabase API를 사용하며 실제 사용자 계정이나 기록을 변경하지 않습니다.

체크 시 화면 흔들림 수정 후에는 빌드와 관련 브라우저 검사 12개를 통과했습니다. 지연된 저장 응답 중에도 PC 1440px·모바일 390px에서 로딩 문구가 생기지 않고 카드·스크롤 위치를 유지하는지 프레임별로 검사합니다. 세부 체크·해제, 부모 체크와 기존 단일 할 일 체크 후 전체 재조회가 없으며, 상세 입력 중 수정 내용과 새로고침 후 완료 상태도 보존합니다.

개별 체크·해제, 부모 연동, 전체 가중 진행률, 같은 텍스트의 독립 항목, 수정·추가·삭제 후 상태, 새로고침, 지연된 응답 전 즉시 표시, 권한 오류 시 복구와 기존 입력·첨부·달력·통계를 검사합니다. 1440px PC, 1280px·800px 태블릿, 390px·360px 모바일에서 가로 넘침과 체크·입력·삭제 영역을 확인합니다. 실제 Galaxy Tab 기기나 OS 키보드 검사는 포함하지 않습니다.
