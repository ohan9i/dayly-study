복제 대상은 **저장된 제목·세부 항목 텍스트·순서**입니다. 계획 ID와 모든 세부 항목 ID를 새로 발급하며, 완료 상태는 모두 false입니다. 작성자는 실행한 사용자, 생성·수정 시각은 기존 DB 기본값을 사용합니다. 원본 작성자·체크한 사람·완료 시각·revision·기록·이미지·파일을 복제하지 않습니다. 복제본을 수정해도 원본은 바뀌지 않습니다.

복제 대상 공간은 현재 선택한 공간으로 고정해 화면에 이름을 표시합니다. 다른 공간으로 옮기려면 기존 이동 기능을 사용할 수 있습니다. 저장하지 않은 수정이나 선택한 첨부는 복제에 포함되지 않는다는 안내를 표시합니다. 복제 날짜 선택에는 기존 작성 폼과 동일한 네이티브 날짜 입력을 사용합니다.

기존 문자열 메모, 진행 상태 JSON, 네이티브 `detail_items` 배열을 기존 `normalizeTask`로 읽습니다. 새 계획 저장과 복제는 같은 INSERT 함수를 사용합니다. 없는 열 오류에만 기존 호환 저장을 재시도하며, 권한 오류나 저장 여부를 확신할 수 없는 네트워크 오류는 자동 재시도하지 않습니다.

| **A. 기존 작성창에서 제목·세부 항목 입력 흐름 단축** | 한 창에서 제목과 세부 항목을 연속 입력. PC의 포커스 이동·저장 단축키, 모바일의 저장 버튼 접근 개선 | 작성창을 여는 동작은 유지                                                      | `TaskDetail`·`DetailItemsEditor` 그대로 개선. 기존 Enter·빈 줄 Backspace 동작을 우선 재사용 | 서버 변경 없음 | 낮음~중간 |
| B. 계획 카드 안에 제목+세부 항목 편집기 펼치기       | 제목과 항목을 같은 자리에서 작성. 화면 전환이 줄어듦                                               | 카드가 커지고 모바일에서 목록·키보드가 경쟁. 첨부는 기존 상세 흐름과 연결 필요 | 기존 항목 편집기 재사용 가능, 폼 경계·초안 유지 설계 필요                                   | 서버 변경 없음 | 중간      |
| C. 여러 줄 붙여넣기 입력                             | 첫 줄은 제목, 나머지는 항목으로 해석해 미리보기 후 저장. 기존 메모를 붙여넣기 편리                 | 줄의 의미가 익숙하지 않으면 오입력. 모바일 한글 입력·개행 주의 필요            | 기존 저장과 편집기 재사용, 해석·미리보기만 추가                                             | 서버 변경 없음 | 중간      |

**추천은 A입니다.** 이미 있는 세부 항목 Enter 동작을 활용하면 제목만 적고 나중에 상세를 다시 여는 불편 없이 개선할 수 있습니다. 별도 빠른 입력창을 만들 이유도 적습니다. 세 방식 모두 닫기·공간 변경·로그아웃 때 작성 내용을 어떻게 보존할지 명시해야 합니다. 초안 보존은 사용자·공간별로 구분하고, 다른 계정에 노출되지 않는 방식으로 설계해야 합니다.

선택할 사항은 **A/B/C 중 입력 흐름**입니다. 제목만 입력하고 세부 항목은 다른 창에서 작성하는 빠른 입력 기능은 추가하지 않았습니다.

## 6. 남아 있는 문제

- 실제 iPhone Safari/Android의 키보드·날짜 선택기, Windows 125~150% 배율, 큰 글자 설정은 추가 확인이 필요합니다.
- 실제 Supabase 운영 계정으로 파일 업로드·다인 동시 복제와 장기 Realtime 연결을 직접 시험하지 않았습니다. 운영 기록은 만들거나 바꾸지 않았습니다.
- 현재의 공동 완료 모델을 사용자마다 독립적인 완료 모델로 바꾸지 않았습니다.
- 네트워크 응답이 끊겨 저장 여부가 불분명하면 자동 재시도하지 않습니다. 새로고침으로 생성 여부를 확인하는 편이 안전합니다. 여러 기기에서 별도로 실행한 복제는 각각 새 계획으로 처리됩니다.
- Vite의 기존 500kB 초과 번들 경고는 남아 있습니다. 기능·권한 변경과 무관한 대규모 코드 분할은 이번 작업에 포함하지 않았습니다.
- 미완료 계획 관리와 빠른 입력은 사용자가 방식 선택 후 구현할 대상입니다.
