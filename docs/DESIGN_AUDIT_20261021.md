# Dayly 디자인·인터랙션 개선안

검토일: 2026년 10월 21일 · 대상: https://ohan9i.github.io/dayly-study/

## 1. 결론과 검토 범위

현재 어색함의 주된 원인은 **각각 다른 규칙으로 만든 버튼과 애니메이션을 한 화면에서 사용한다는 것**이다. 기록을 여는 버튼, 체크박스, 밀어서 여는 작업, 길게 누르는 실행 버튼, 일반 확인창이 서로 다른 방식으로 반응한다. 기능을 추가하기보다 **색상의 역할, 조작 단계, 움직이는 범위**를 통일하는 작업이 먼저다.

이 문서는 개선 제안이다. 서비스 화면과 동작 코드를 수정하거나 배포하지 않았다.

### 반드시 보존할 부분

- 첫 진입 화면 전체의 현재 디자인과 책·표지·진입 연출은 이번 개선 대상으로 삼지 않는다.
- 메인 화면의 LiquidChrome 배경, 색상, 움직임, 속도, 조명, 배경 위 덮개와 그라데이션을 유지한다.
- 배경을 흐리게 하거나 다른 색으로 덮어 UI 문제를 해결하지 않는다.
- 낮·밤 배경도 현재 모습을 유지한다. 테마 스위치의 버튼 자체만 개선할 수 있다.

**주의할 코드 구조:** `PlannerBackground.css`의 배경은 `--studio`, `--surface-soft`, `--surface-selected`를 사용한다. 버튼을 정리하려고 이 공통 변수를 바꾸면 배경도 달라질 수 있다. 버튼·기록 영역에 전용 `--ui-*` 변수를 적용하고, 배경이 참조하는 기존 변수는 고정해야 한다.

### 확인 방법과 한계

- **화면 확인:** 공개 사이트에서 첫 화면 진입, 메인 목록, 기록 열기·접기, 할 일 상세, 빈 날짜, 달력, 학습 흐름, 설정, 로그인·회원가입 탭, 검색을 직접 확인했다. 관찰한 브라우저 너비는 약 534px인 좁은 화면이다.
- **코드 확인:** 로컬 작업 폴더의 React 컴포넌트, CSS, 기존 구현 문서를 확인했다. 검토 시작 시 Git 작업 폴더는 깨끗했고 최신 커밋은 `2b779fb`였다.
- **미실행:** 로그인 후 실제 기록 저장, 첨부 업로드, 삭제, 복제, 공간 이동은 실행하지 않았다. 해당 부분은 로컬 코드에 근거한 구조 검토이며 배포본에서 재현한 결과와 구분한다.
- 320·390px 및 데스크톱, 실제 모바일 터치, 밤 모드의 전체 동작을 직접 검증했다고 주장하지 않는다. 배포본과 로컬 코드가 완전히 같은 버전인지도 별도로 확정하지 않았다.
- 아래의 ‘위험’ 표시는 코드에서 확인한 가능성이다. 실제 사용자 데이터 손실이나 프레임 저하가 발생했다고 단정하는 표현이 아니다.

## 3. 권장하는 최종 조작 방식

### 기록

1. 세부 항목 오른쪽 `기록 2 ▾`를 누른다.
2. 같은 항목 아래에 저장된 기록과 `+ 기록 작성`이 나타난다.
3. 작성하면 `취소 / 기록 저장`이 보인다. 파일 첨부는 보조 동작으로 둔다.
4. 저장 중에는 같은 자리에 `저장 중…`, 완료 후에는 짧은 `저장됨` 안내를 표시한다.
5. 접었다 다시 열어도 작성 중인 내용이 유지된다. 다른 항목의 기록을 자동으로 닫아 초안을 잃게 하지 않는다.

**색상 역할:** 닫힌 기록 버튼은 투명한 중립 텍스트, 열린 기록 버튼은 옅은 선택 면, 저장 버튼은 진한 주 실행색이다. 본문 전체가 눌린 버튼처럼 칠해지지 않게 한다. 열린 상태, 마우스를 올린 상태, 키보드 초점을 서로 다른 규칙으로 표현한다.

### 추가·삭제

- 계획 추가: 카드 상단 `+ 계획 추가` 한 곳을 주 경로로 사용한다. 모바일에서 `+`만 보이더라도 접근 가능한 이름과 일관된 위치를 유지한다.
- 세부 항목 추가: 편집 화면 안에서 `+ 세부 항목 추가`를 사용한다.
- 계획 관리: 제목 행의 `⋯ → 복제 / 다른 공간으로 이동 / 휴지통으로 이동`을 사용한다.
- 모바일 왼쪽 밀기: 유지한다면 휴지통 작업을 드러내는 선택적 단축 경로로 둔다. 작업 면 자체를 버튼으로 사용한다.
- 휴지통 이동: 작업 선택 → 대상이 표시된 확인창 → `휴지통으로 이동`. 긴 누름은 제거한다.
- 복제·이동: 대상 선택 → 구체적인 실행 버튼 → 처리 결과. 일반 버튼으로 수행한다.

삭제는 기존 서버의 복구·권한 정책을 따른다. 계획, 세부 항목, 업로드 대기 파일은 복구 조건이 다르므로 **모두 같은 되돌리기 정책으로 묶지 않는다.** 특히 세부 항목에 계획 휴지통과 같은 복원 기능이 있다고 안내해서는 안 된다. 첫 개선에서는 현재 확인창을 유지하고 중복된 긴 누름을 없애는 편이 변경 범위를 관리하기 쉽다.

## 4. 공통 시각 규칙

기존 종이색과 따뜻한 중립색을 기준으로 정돈한다. 새 브랜드 색을 추가하는 작업이 아니다. 아래 값은 **메인 UI에만 적용할 제안값**이며 실제 대비·밤 모드 검증 후 확정한다.

| 역할 | 권장 규칙 |
| --- | --- |
| 주 실행 | 저장·로그인 등에만 진한 채움. 기존 `--accent-solid`의 인상을 유지하고 UI 전용 별칭으로 관리한다. |
| 보조 실행 | 외곽선 또는 옅은 면. 파일 첨부·복제 열기·취소 등을 구분한다. |
| 펼치기 | 평소 투명, 열린 상태만 옅은 선택 면. 색과 화살표를 함께 사용한다. |
| 위험 동작 | 위험 텍스트+휴지통 아이콘. 마지막 확정에만 위험 채움. 기존 `#9b4541` 계열을 검토한다. |
| 초점 | 명확한 2px 외곽선과 간격. 단순 호버와 구별한다. |
| 비활성 | 비활성 이유를 가까이 안내한다. 읽기 콘텐츠 전체를 회색 비활성 폼으로 바꾸지 않는다. |
| 곡률 | 컨트롤 8px / 인라인 패널 12px / 카드 16px / 대화상자 20px을 시작 기준으로 검토한다. |
| 크기 | 기본 컨트롤 데스크톱 40px, 터치 영역 44px 이상. 아이콘은 대체로 16px, 선 굵기도 통일한다. |
| 간격 | 4·8·12·16·24·32px 체계. 버튼 주변 간격과 기록 들여쓰기를 화면별 임의 값으로 추가하지 않는다. |
| 글자 | 본문 15~16px, 보조 13px 전후, 모바일 입력 16px. 제목·세부 항목·기록의 위계를 유지한다. |

모든 버튼을 진한 채움으로 만들면 강조가 사라진다. 화면 또는 작성 영역마다 가장 중요한 실행을 먼저 정하고 나머지는 한 단계 낮춘다.

## 5. 애니메이션 정리 기준

현재 코드에는 이미 동작 줄이기 설정, 키보드 입력 시 효과 축소, 44px 터치 영역, 대화상자 초점 복귀 등 좋은 기반이 있다. 이를 유지하면서 서로 다른 표현을 줄이는 방향이 적절하다. 배경과 첫 화면의 애니메이션은 이 표의 변경 대상에서 제외한다.

| 요소 | 제안 | 적용 이유 |
| --- | --- | --- |
| 일반 버튼 누르기 | 100~120ms의 미세한 명도 변화. 위치 이동 생략. | 즉시 반응하면서 화면을 흔들지 않는다. |
| 기록 펼치기 | 본문 내부 투명도 140~180ms, 화살표는 같은 리듬. | 상태 변화가 연결돼 보이게 한다. |
| `⋯` 메뉴 | 140~180ms, 투명도+최대 4px 이동. 트리거 쪽을 기준점으로 설정. | 무엇에서 나온 메뉴인지 설명한다. |
| 삭제 확인창 | 등장 180~220ms, 퇴장 120~160ms. 중첩 확인은 제거. | 확인 단계의 존재는 유지하면서 지연을 줄인다. |
| 체크박스 | 체크 표시 120~180ms. 큰 바운스와 완료 숫자 이동 제거. | 매일 반복하는 조작의 시각적 피로를 줄인다. |
| 진행 막대 | 180~220ms 또는 즉시. 가능하면 `scaleX`로 구현. | 너비 애니메이션의 레이아웃 비용을 줄인다. |
| 메뉴 전환 | 즉시 전환 또는 콘텐츠 120ms 페이드. 스크롤 위치 정책을 먼저 수정. | 애니메이션으로 잘못된 화면 위치를 가리지 않는다. |
| 테마 스위치 자체 | 160~200ms, 늘어남 최소화. | 보조 컨트롤의 표현을 다른 버튼과 맞춘다. |

기본 감속 곡선은 현재 계열과 가까운 `cubic-bezier(0.22, 1, 0.36, 1)` 한 가지로 시작한다. 색상은 짧은 전환을 허용하되, 레이아웃 속성과 복잡한 마스크를 반복 애니메이션하는 것은 줄인다. 키보드와 동작 줄이기에서는 움직임을 생략하거나 짧은 투명도 변화만 제공한다.

완료 축하 효과는 하루 전체 완료 같은 드문 순간에만 남길 수 있다. 현재 그런 조건과 모바일·동작 줄이기 제외 처리가 있으므로, 단순히 코드가 존재한다는 이유로 전부 제거할 항목은 아니다. 실제 프레임 저하는 이번 검토에서 측정하지 않았다.

## 7. 개선 완료 판정 기준

아래는 향후 구현을 검증할 기준이다. 이번 문서 작성에서 모두 실행한 테스트 목록은 아니다.

- [ ] 첫 화면과 메인 배경 관련 코드·파라미터에 변경이 없다. 움직이는 배경은 임의 시점 스크린샷의 픽셀 일치로 판정하지 않고 코드 변경 범위와 같은 조건의 관찰로 확인한다.
- [ ] 기록 버튼은 포인터를 치워도 열린 상태가 명확하다. 부모 계획 전체에 원치 않는 호버 면이 생기지 않는다.
- [ ] 기록 작성 → 접기 → 다시 열기에서 글이 유지된다. 선택 파일의 유지 범위도 안내와 일치한다.
- [ ] 작성 중 날짜·공간·메뉴 이동, Escape·배경 클릭·닫기에서 초안 정책이 일관된다.
- [ ] 저장 실패 후 작성 내용과 성공한 첨부는 유지되고, 재시도 시 중복 기록이 생기지 않는다.
- [ ] 저장 중 상태가 보이며 저장 버튼 폭과 입력창 위치가 불필요하게 바뀌지 않는다.
- [ ] 마우스만으로 모든 계획 작업을 찾고 실행할 수 있다. 키보드로도 더보기·확인·취소가 가능하다.
- [ ] 실제 모바일에서 세로 스크롤, 체크, 기록 버튼, 텍스트 선택이 밀기와 충돌하지 않는다.
- [ ] 긴 제목·여러 세부 항목·펼친 기록이 있어도 작업 메뉴가 대상 제목 근처에 있다.
- [ ] 휴지통 이동은 명확한 한 번의 확인으로 끝나며, 기존 복구·권한 정책이 유지된다.
- [ ] 메뉴 이동 후 새 화면 제목이 보인다. 학습 흐름에서 날짜를 바꿔도 그 화면을 유지한다.
- [ ] 세부 항목 검색 결과에 일치한 문장이 표시된다. 검색을 열면 바로 입력할 수 있다.
- [ ] 320·390·420·768·1440px에서 줄바꿈·터치 영역·목록 밀도·창 내부 스크롤을 확인한다.
- [ ] 낮·밤에서 기본·호버·열림·눌림·초점·비활성·처리 중·오류 상태를 모두 확인한다.
- [ ] 동작 줄이기와 키보드 조작에서도 상태가 분명하며 이동·바운스가 강제되지 않는다.
- [ ] 수정 후 필요한 기존 브라우저 테스트를 갱신한다. 긴 누름 제거 등 의도된 사양 변경을 기존 테스트 기대값과 함께 정리한다.

**권장 방향:** 현재의 배경과 종이 같은 인상을 유지하면서, 계획을 읽고 체크하고 기록하는 동작은 더 적은 단계와 더 일정한 규칙으로 만든다. 애니메이션 추가보다 **중복 조작 제거 → 상태 구분 → 색상과 간격 통일 → 필요한 움직임만 정리** 순서가 효과적이다.
