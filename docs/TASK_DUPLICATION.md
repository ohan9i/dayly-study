# 공유 계획 복제

2026-10-19: 같은 공유 공간의 다른 참여자가 복제 버튼 비활성과 권한 오류를 경험했다는 보고를 조사했습니다. 운영 서버의 기존 승인·INSERT 정책은 정상이었고, 승인된 비작성자 권한으로 실행한 저장도 롤백 트랜잭션에서 성공했습니다. 조회한 최근 하루의 4xx 로그에는 실패 요청이 없어서 과거 실패의 직접 원인을 확정하지는 못했습니다.

코드에서는 완료 목록 등 핵심 조회가 한 번 실패하면 `readiness.core`가 내려가면서 기존에 읽은 계획의 복제도 함께 잠기는 경로를 확인했습니다. 복제는 완료 목록을 필요로 하지 않으므로, 이 동작을 분리했습니다.

## 동작과 권한

- `duplicate_task`가 이메일 확인이 끝난 현재 공간 참여자인지 다시 검사합니다. 원본 작성자의 편집 권한은 요구하지 않습니다.
- 현재 공간에 남아 있는 활성 원본을 잠근 뒤 최신 제목과 세부 항목 순서를 하나의 INSERT로 복제합니다. 삭제되거나 이동된 원본, 미승인·로그아웃 계정의 요청은 거부합니다.
- 복제본의 작성자는 요청한 계정입니다. 항목 ID는 새로 만들고 완료 표시·수행 기록·첨부는 가져오지 않습니다.
- 기존 수정·이동·휴지통·복구·원본 보존 정책은 변경하지 않습니다. 기존 생성 이력과 변경 알림 트리거가 복제에도 실행됩니다.
- 완료 목록 조회 실패가 복제 버튼까지 잠그지 않습니다. 계정·공간 전환, 비밀번호 복구, 진행 중인 작업과 중복 제출에 대한 기존 잠금은 유지합니다.
- 권한 거부와 서버 함수 미설치는 각각 안내하며, 실패한 요청을 다른 저장 경로로 재시도하지 않습니다.

## 적용 순서

`20261017_recoverable_member_actions.sql` 이후에 `supabase/migrations/20261019_member_task_duplication.sql`, `supabase/migrations/20261019_compact_task_duplication.sql` 순서로 적용하고 새 프런트엔드를 배포합니다. 새 SQL은 반복 실행할 수 있으며 기존 데이터와 일반 테이블 권한을 바꾸지 않습니다. 기존 프런트엔드도 계속 동작하므로 서버를 먼저 적용합니다.

## 검증

`recoverable-member-actions.test.ts`는 기존 보호 정책을 모두 적용한 상태에서 실제 PostgreSQL 엔진으로 비작성자 복제, 새 작성자·항목 ID, 완료 초기화, 원본과 기록 보존, 생성 이력, 미승인·비로그인 계정 거부와 삭제된 원본 거부를 검사합니다.

`task-duplication.spec.ts`는 브라우저에서 비작성자 복제, 원본과 첨부 보존, 중복 제출 차단, 권한 오류·서버 미설치 때 부분 복제 방지와 완료 목록 조회 실패 후 복제를 검사합니다. 브라우저 API는 테스트용 응답이며, 운영 서버 검증은 별도의 롤백 트랜잭션으로 수행합니다.

이번 변경에서는 전체 단위·SQL 테스트 70개와 복제·공유 체크·이동·삭제·접근 복구 브라우저 테스트 19개가 통과했습니다. 운영 서버에도 SQL을 적용했으며 기존 승인된 비작성자 역할로 실행한 복제에서 생성 1건, 요청자 작성자, 같은 공간, 완료 초기화, 원본 보존과 하위 기록 미복제를 확인했습니다. 이 검증 트랜잭션은 마지막에 롤백해 시험 계획과 이력을 남기지 않았습니다.

## 후속 회귀 검사

추가 디버깅에서 브라우저가 정상 저장한 10,000자 진행 데이터도 복제 시 `jsonb::text`가 구조용 공백을 추가해 `tasks_details_check` 제약을 위반하는 경계값 오류를 재현했습니다. 후속 마이그레이션은 복제 데이터의 구조용 공백만 없애며, 각 문자열은 `to_json`으로 인코딩해 사용자가 입력한 공백·따옴표·역슬래시·탭·줄바꿈을 보존합니다. 저장 한도와 권한 정책은 유지됩니다.

최대 길이 계획 및 완료된 제목 전용 계획의 복제 회귀 테스트를 추가했습니다. 수정 후 전체 단위·SQL 테스트 72개, 전체 브라우저 테스트 55개, TypeScript 검사 및 운영 빌드가 통과했습니다. 브라우저 테스트는 복제·공유 체크·이동·삭제 복구·첨부·접근 복구·모바일 레이아웃을 포함하며 API 응답은 모의 서버를 사용합니다.

운영 DB에 후속 마이그레이션을 적용한 후 승인된 비작성자 역할의 롤백 검증에서도 최대 길이 복제, 텍스트 보존, 복제본 작성자·공간, 원본 보존, 제목 전용 계획의 완료 초기화가 모두 참으로 확인됐습니다. 검증 데이터는 트랜잭션 종료 시 롤백했습니다.
