# Dayly — 나의 공부, 나의 하루

하늘빛, 바다와 창가, 반투명 카드를 사용한 개인 학습 대시보드입니다. 폴더에 제공된 `차분한 하루 플래너 대시보드.png`를 전체 디자인 기준으로, `아이콘.png`를 아이콘과 버튼의 세부 디자인 기준으로 만들었습니다.

**홈페이지:** <https://ohan9i.github.io/dayly-study/>

**코드 저장소:** <https://github.com/ohan9i/dayly-study>

## 바로 사용하기

1. 오른쪽 위 계정 버튼 → **회원가입**에서 이메일과 비밀번호를 입력합니다. 비밀번호는 8자 이상이며 확인란에 한 번 더 입력합니다.
2. 가입 확인 이메일의 링크를 누른 뒤 **로그인**하면 **내 공간이 자동으로 준비**됩니다. 다른 사람이 승인한 곳은 홈의 공간 선택 목록과 설정에서 **승인받은 공간**으로 구분됩니다. 사용할 공간을 직접 선택하고, 설정에서 내 공간의 이름을 바꿀 수 있습니다.
3. `오늘 할 일` 오른쪽의 `+`로 제목과 날짜를 작성합니다. **세부 항목**은 선택사항이며, 한 줄씩 자유롭게 적습니다. `한 줄 추가` 또는 내용이 있는 줄에서 Enter를 누르면 새 입력칸이 생깁니다. `×`는 해당 줄만 삭제하고, 빈 줄의 Backspace는 이전 줄로 이동합니다. 빈 줄과 공백은 저장할 때 제외합니다. **파일 첨부**에서 PDF, JPG, PNG, WebP를 고른 다음 저장합니다. 파일당 10MB이며 한 번에 5개까지 선택합니다.
4. 세부 항목 왼쪽에서 각각 완료 체크를 할 수 있습니다. 얇은 진행 바에는 완료한 항목 수가, 날짜 옆 작은 원에는 그날의 전체 진행률이 표시됩니다. 모두 체크하면 메인 할 일도 완료되고, 메인 체크를 누르면 모든 세부 항목을 함께 체크하거나 해제합니다. 해당 공간에 승인된 참여자 모두 체크·해제할 수 있으며 다른 참여자의 변경도 자동 반영됩니다.
5. 메뉴에서 달력, 최근 7일의 학습 흐름, 설정으로 이동합니다. 휴대폰에서는 하단에 메뉴가 있습니다. 달력의 막대는 진행률, 작은 숫자는 남은 계획 개수입니다. 세부 항목이 없는 할 일은 1개로 계산하고 모두 완료한 날짜에는 남은 숫자를 표시하지 않습니다.
6. 오른쪽 위 돋보기로 할 일 제목과 세부 항목을 검색합니다.
7. `설정 → 나의 기록 보관 → 백업 내려받기`로 기록을 보관합니다. 계정 화면에서 비밀번호 변경과 로그아웃도 할 수 있습니다.
8. 내가 작성한 항목 또는 내 공간의 항목은 상세보기의 **다른 플래너로 이동**에서 접근 가능한 다른 공간으로 옮깁니다. 내 공간을 먼저 표시하며 날짜·세부 항목·완료·기록·첨부를 유지합니다. 성공하면 대상 공간으로 전환합니다.
9. 상세보기 하단의 **이 계획 복제**에서 날짜를 고르면 현재 선택한 공간에 새 계획을 만듭니다. 제목과 세부 항목의 순서만 가져오며 완료 상태·기록·첨부는 제외합니다. 승인된 참여자는 다른 사람이 작성한 계획도 복제할 수 있고, 복제본의 작성자는 복제를 실행한 사람입니다. 저장하지 않은 편집 내용은 먼저 저장해야 복제에 반영됩니다.

할 일 제목을 누르면 상세 창에서 제목·날짜·세부 항목을 수정하고 자료 파일을 확인합니다. 수행 내용은 메인 목록의 각 세부 항목 옆 **기록**을 펼쳐 글과 풀이 사진을 남깁니다. 상세 창에는 별도의 수행 내용 영역을 표시하지 않습니다. 업로드 실패 시 성공한 파일을 유지하고 실패한 파일만 다시 저장할 수 있습니다. 이전 할 일 단위 수행 기록과 삭제된 세부 항목의 기록은 데이터와 JSON 백업에 보존됩니다.

다른 참여자의 변경은 Realtime 알림과 공간 변경 번호 확인으로 반영합니다. 변경이 있을 때만 데이터를 다시 읽고 작성 중인 글과 커서·파일 선택을 유지합니다. 오른쪽 위 **공유 기록 새로고침** 버튼으로 공간 접근 권한도 다시 확인할 수 있습니다. 로그인, 공간 선택과 저장 완료 시에는 최신 기록을 불러옵니다.

홈에서는 작은 클립 아이콘으로 첨부 개수만 표시합니다. 날짜는 한 줄로 정리하고 글자 크기와 간격을 키웠습니다. JSON 백업은 글과 파일 목록을 보관하며 파일 원본은 각 카드에서 별도로 내려받습니다.

세부 항목 텍스트는 `details: string[]`, 체크 상태는 같은 순서의 `detailChecks: { id, completed, completedBy?, completedAt? }[]`로 관리하고 백업합니다. 기존 문자열 메모와 localStorage v1 기록도 읽을 때 변환하며 과목·시간 저장값은 호환성을 위해 보존합니다. Supabase의 텍스트 열에 항목 ID·텍스트·완료 상태를 담은 버전 표시 JSON과 네이티브 텍스트 배열을 함께 저장합니다. **공유 체크와 이동에는 `20261006_shared_checks_and_moves.sql` 적용이 필요합니다.** 자세한 내용은 [공유 체크·이동 구현 기록](docs/SHARED_CHECKS_AND_MOVES.md), [세부 항목 구현 기록](docs/TASK_DETAIL_ITEMS.md), [진행률 구현 기록](docs/TASK_PROGRESS.md)에 있습니다.

**현재는 Supabase 계정 로그인 방식입니다.** 로그인 전에는 예시 일정 또는 이 브라우저의 이전 개인 기록을 조회합니다. 할 일 추가, 수정, 삭제와 완료 체크에는 로그인이 필요합니다. 공유 데이터베이스도 비로그인 방문자의 접근을 거부합니다.

로그인 후 작성한 할 일은 승인된 Supabase 공간에 저장됩니다. 같은 계정으로 다른 기기에서 로그인하면 해당 공간을 볼 수 있습니다. 기존 브라우저의 개인 기록은 자동으로 업로드하지 않으며, 로그인 전에 백업을 내려받을 수 있습니다.

비밀번호를 잊으면 로그인 화면의 **비밀번호를 잊었나요?**에서 재설정 메일을 받습니다. 메일의 링크로 돌아와 새 비밀번호를 저장하면 재설정이 끝납니다.

공부 기록 작성 화면과 메뉴는 제거했습니다. 기존 브라우저에 저장했던 공부 기록은 화면과 통계에 나타나지 않지만, 이전 백업과의 호환성을 위해 백업 데이터 안에 유지됩니다.

## 내 컴퓨터에서 실행하기

`ML` 폴더에서 PowerShell을 연 뒤 다음 명령을 한 줄씩 실행합니다.

```powershell
Set-Location -LiteralPath '.\git homepage'
npm install
npm run dev
```

브라우저에서 <http://127.0.0.1:5173/>을 엽니다. 서버를 종료하려면 명령을 실행한 창에서 `Ctrl+C`를 누릅니다.

- `npm install`: 이 홈페이지가 사용하는 라이브러리를 설치합니다. 처음 실행하거나 라이브러리가 변경되었을 때 필요합니다.
- `npm run dev`: 수정한 코드가 바로 반영되는 개발 서버를 시작합니다.
- `npm run build`: 배포할 파일을 `dist` 폴더에 만듭니다. TypeScript 검사도 함께 수행합니다.
- `npm run preview`: 만들어진 배포 파일을 <http://127.0.0.1:4173/>에서 확인합니다.
- `npm test`: 날짜, 백업 데이터, 실제 SQL의 접근 권한을 검사합니다.
- `npm run test:e2e`: 자동 브라우저로 로그인과 계정, 제목·세부 항목 작성과 키보드 동작, 기존 메모와 DB 호환, 새로고침, 검색, 달력, 통계, 백업, 첨부와 휴대폰 화면을 검사합니다. 계정 API 응답은 테스트용으로 대체하여 실제 가입이나 이메일 발송을 하지 않습니다. 연결 정보가 들어간 빌드가 필요하며, 처음에는 `npx playwright install chromium`이 필요합니다.

Node.js 24를 기준으로 작성하고 검사했습니다.

## GitHub Pages 배포

GitHub Pages는 홈페이지 화면을 게시하고, Supabase는 공유 모드의 계정과 기록을 저장합니다. [GitHub Pages 설명](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [Vite의 배포 안내](https://vite.dev/guide/static-deploy.html)

저장소에서 `Settings → Pages → Source → GitHub Actions`를 선택합니다. `main` 브랜치에 코드를 올리면 `.github/workflows/deploy.yml`이 검사, 빌드, 배포를 수행합니다. 상대 경로를 사용해 `/저장소이름/`에서도 배경과 글꼴이 로드됩니다.

코드를 수정한 뒤 PowerShell에서 실행합니다.

```powershell
git status
git add src
git commit -m "Update study dashboard"
git push
```

- `git status`: 수정된 파일을 확인합니다.
- `git add`: 이번에 기록할 변경 파일을 선택합니다. 다른 폴더를 수정했으면 해당 경로도 지정합니다.
- `git commit`: 변경 내용에 이름을 붙여 내 컴퓨터의 Git 이력에 기록합니다.
- `git push`: 기록한 변경을 GitHub로 보내 자동 배포를 시작합니다.

GitHub 저장소에 개인 할 일이나 계정 비밀번호를 저장하지 않습니다. Supabase의 공유 기록은 아래의 데이터베이스 정책으로 보호합니다.

## 로그인과 공유 설정

설정 순서는 [공유 기능 연결 안내](docs/SUPABASE_SETUP.md)에 자세히 적었습니다. 필요한 것은 **프로젝트 URL과 publishable key**입니다. `secret` 또는 `service_role` key는 프런트엔드에 넣지 않습니다. [Supabase 공개 키와 데이터 보호 안내](https://supabase.com/docs/guides/database/secure-data)

| 동작                                 | 본인 / 관리자 | 승인된 작성자 | 미승인 계정, 비로그인 방문자 |
| ------------------------------------ | ------------- | ------------- | ---------------------------- |
| 해당 공유 공간의 기록 보기           | 가능          | 가능          | 불가능                       |
| 할 일 작성                           | 가능          | 가능          | 불가능                       |
| 본인이 작성한 항목 수정, 삭제        | 가능          | 가능          | 불가능                       |
| 다른 사람이 작성한 항목 수정, 삭제   | 가능          | 불가능        | 불가능                       |
| 완료 체크                            | 가능          | 가능          | 불가능                       |
| 읽을 수 있는 계획을 현재 공간에 복제 | 가능          | 가능          | 불가능                       |
| 작성자 승인, 권한 해제               | 가능          | 불가능        | 불가능                       |

이메일 확인 후 로그인한 사람에게는 자신의 공간이 자동으로 준비됩니다. 다른 사람의 공간은 그 공간의 관리자가 별도로 승인해야 보입니다. 처음에는 내 공간을 열고, 이후에는 계정별로 마지막 선택을 기억합니다.

승인된 사람도 할 일에 수행 내용과 파일을 남길 수 있습니다. 본인의 수행 내용을 수정하거나 삭제할 수 있고, 관리자는 전체 내용을 관리합니다. 본인이 만든 할 일을 삭제하면 그 할 일에 속한 수행 내용과 첨부도 함께 삭제됩니다. Storage 버킷은 비공개이며 현재 공간의 권한을 검사합니다. 미리보기 링크는 2분 후 만료됩니다.

로그아웃하면 공유 기록이 화면에서 제거되고 편집이 잠깁니다. 해당 브라우저에 이전 개인 기록이 있으면 조회 화면에 나타납니다. 백업 내려받기는 제공하지만, 로그인 방식에서는 JSON 파일을 데이터베이스로 불러오는 기능을 제공하지 않습니다.

Supabase 프로젝트와 GitHub 배포 변수에 연결 정보를 설정했습니다. 추가 SQL을 실행했으며, 실제 서버에서 새 테이블과 내 공간 생성 함수의 비로그인 접근이 거부됨을 확인했습니다. SQL 권한은 로컬 PostgreSQL 엔진(PGlite)에서, 화면 흐름은 테스트용 API를 사용하는 브라우저에서 검사합니다. 실제 계정으로 파일을 저장하고 여러 사람끼리 사용하는 과정은 로그인한 사용자 세션에서 확인할 수 있습니다.

## 디자인 배경

본문과 큰 시계는 **Pretendard Variable**, Dayly 로고는 **Caveat**을 사용합니다. 큰 제목은 굵기 500, 카드 제목은 600, 할 일은 450, 오늘의 문구는 350입니다. 큰 제목의 자간은 `-0.035em`, 줄 높이는 `1.4`입니다. 글꼴을 홈페이지와 함께 배포하고 필요한 글자의 WOFF2 서브셋을 불러옵니다. 설정과 출처는 [디자인 기록](design/ASSETS.md)에 적었습니다.

창가의 공부 플래너라는 구도를 유지하면서 96px 사이드바, 빛이 은은하게 비치는 카드, 절제된 시계와 통일된 선형 아이콘으로 다듬었습니다. 달력은 강조할 날짜만 표시하고 통계 요약은 하나의 띠로 정리했습니다. 제목 아래에는 세부 항목을 작고 차분한 목록으로 배치하고 보조 글자도 12px 이상으로 표시합니다. 공통 색상·여백·곡률·애니메이션 규칙과 검증 결과는 [디자인 시스템](docs/DESIGN_SYSTEM.md)에 있습니다.

참고 이미지의 UI를 실제 HTML 요소로 다시 만들고, 배경에서는 UI를 제거했습니다. 추가한 아이콘 참고 이미지의 선 모양, 파란색 활성 메뉴, 원형 추가 버튼과 색상 점 태그를 화면에 반영했습니다. 아이콘은 SVG로 표시하여 확대해도 선명합니다. 배경 생성 방식과 최종 프롬프트는 [이미지 제작 기록](design/ASSETS.md)에 보관했습니다. 자체 호스팅하는 글꼴과 아이콘에는 해당 npm 패키지의 라이선스가 적용됩니다.

2026-10-08 개선의 구현 범위·검증 결과와 아직 구현하지 않은 두 기능의 대안은 [사용성 개선 보고서](docs/DAYLY_USABILITY_20261008.md)에 정리했습니다.
