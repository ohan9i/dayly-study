# Dayly — 나의 공부, 나의 하루

하늘빛, 바다와 창가, 반투명 카드를 사용한 개인 학습 대시보드입니다. 폴더에 제공된 `차분한 하루 플래너 대시보드.png`를 디자인 기준으로 만들었습니다.

**홈페이지:** <https://ohan9i.github.io/dayly-study/>

**코드 저장소:** <https://github.com/ohan9i/dayly-study>

## 바로 사용하기

1. 첫 화면에는 기능을 살펴볼 수 있는 **예시 일정**이 있습니다. `비우고 시작`을 누르면 직접 추가한 기록은 남기고 예시 일정만 삭제합니다.
2. `오늘 할 일` 오른쪽의 `+`로 날짜, 시간, 과목과 메모를 작성합니다. 할 일의 제목을 누르면 상세 보기와 수정이 가능합니다.
3. 체크박스를 누르면 완료 상태가 저장됩니다. 새로고침해도 유지됩니다.
4. `오늘의 공부 기록 → 기록하기`에서 공부 내용, 시간, 다음에 공부할 것을 적습니다.
5. 왼쪽 메뉴로 달력, 공부 기록, 최근 7일의 학습 흐름, 설정으로 이동합니다. 휴대폰에서는 하단에 메뉴가 있습니다.
6. 오른쪽 위 돋보기로 할 일과 공부 내용 전체를 검색합니다.
7. `설정 → 나의 기록 보관 → 백업 내려받기`로 기록을 보관합니다.

**현재는 개인 모드입니다.** 기록은 이 브라우저의 `localStorage`에 저장됩니다. 다른 컴퓨터, 다른 브라우저, 다른 사이트 주소의 저장 공간과는 분리됩니다. 브라우저 데이터를 삭제하면 기록도 삭제되므로 백업을 보관하세요. 기록은 GitHub 저장소에 올라가지 않습니다.

공유 모드는 Supabase 프로젝트를 연결한 뒤 사용할 수 있습니다. 화면에 연결되지 않은 로그인이나 작성자 승인이 가능한 것처럼 표시하지 않습니다.

## 내 컴퓨터에서 실행하기

`ML` 폴더에서 PowerShell을 연 뒤 다음 명령을 한 줄씩 실행합니다.

```powershell
Set-Location -LiteralPath '.\git homepage'
npm install
npm run dev
```

브라우저에서 <http://127.0.0.1:5173/>을 엽니다. 서버를 종료하려면 명령을 실행한 창에서 `Ctrl+C`를 누릅니다.

- `npm install`: 이 홈페이지가 사용하는 라이브러리를 설치합니다. 처음 실행하거나 라이브러리가 변경되었을 때 필요합니다.
- `npm run dev`: 수정한 코드가 바로 반영되는 개발 서버를 시작합니다.
- `npm run build`: 배포할 파일을 `dist` 폴더에 만듭니다. TypeScript 검사도 함께 수행합니다.
- `npm run preview`: 만들어진 배포 파일을 <http://127.0.0.1:4173/>에서 확인합니다.
- `npm test`: 날짜, 백업 데이터, 실제 SQL의 접근 권한을 검사합니다.
- `npm run test:e2e`: 자동 브라우저로 기록 작성, 새로고침, 검색, 달력, 통계, 백업, 휴대폰 화면을 검사합니다. 처음에는 `npx playwright install chromium`이 필요합니다.

Node.js 24를 기준으로 작성하고 검사했습니다.

## 파일 구조

| 파일                           | 역할                                         |
| ------------------------------ | -------------------------------------------- |
| `src/App.tsx`                  | 화면, 메뉴, 작성 폼과 사용자 동작            |
| `src/styles.css`               | 색상, 여백, 반투명 카드, 휴대폰 화면         |
| `src/domain.ts`                | 데이터 형식, 날짜 계산, 백업 검사, 통계      |
| `src/planner.ts`               | 개인 저장과 Supabase 로그인·공유 데이터 연결 |
| `public/study-window.webp`     | 실제 홈페이지에서 사용하는 압축된 배경       |
| `design/study-window.png`      | 생성한 배경의 원본                           |
| `supabase/schema.sql`          | 공유 데이터베이스 테이블과 접근 권한         |
| `.github/workflows/deploy.yml` | GitHub Pages 자동 배포                       |

화면 수정은 `App.tsx`와 `styles.css`에서 시작하면 됩니다. 공유 권한은 화면 코드와 데이터베이스 정책을 함께 확인해야 합니다.

## GitHub Pages 배포

GitHub Pages는 홈페이지 화면을 게시하고, Supabase는 공유 모드의 계정과 기록을 저장합니다. [GitHub Pages 설명](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [Vite의 배포 안내](https://vite.dev/guide/static-deploy.html)

저장소에서 `Settings → Pages → Source → GitHub Actions`를 선택합니다. `main` 브랜치에 코드를 올리면 `.github/workflows/deploy.yml`이 검사, 빌드, 배포를 수행합니다. 상대 경로를 사용해 `/저장소이름/`에서도 배경과 글꼴이 로드됩니다.

코드를 수정한 뒤 PowerShell에서 실행합니다.

```powershell
git status
git add src
git commit -m "Update study dashboard"
git push
```

- `git status`: 수정된 파일을 확인합니다.
- `git add`: 이번에 기록할 변경 파일을 선택합니다. 다른 폴더를 수정했으면 해당 경로도 지정합니다.
- `git commit`: 변경 내용에 이름을 붙여 내 컴퓨터의 Git 이력에 기록합니다.
- `git push`: 기록한 변경을 GitHub로 보내 자동 배포를 시작합니다.

GitHub 저장소가 공개되어도 개인 모드의 공부 기록은 각 방문자의 브라우저에만 저장됩니다. Supabase를 연결한 공유 기록은 아래의 데이터베이스 정책으로 보호합니다.

## 나중에 로그인과 공유 연결하기

설정 순서는 [공유 기능 연결 안내](docs/SUPABASE_SETUP.md)에 자세히 적었습니다. 필요한 것은 **프로젝트 URL과 publishable key**입니다. `secret` 또는 `service_role` key는 프런트엔드에 넣지 않습니다. [Supabase 공개 키와 데이터 보호 안내](https://supabase.com/docs/guides/database/secure-data)

| 동작                              | 본인 / 관리자 | 승인된 작성자 | 미승인 계정·비로그인 방문자 |
| --------------------------------- | ------------- | ------------- | --------------------------- |
| 해당 공유 공간의 기록 보기        | 가능          | 가능          | 불가능                      |
| 할 일·공부 기록 작성              | 가능          | 가능          | 불가능                      |
| 본인이 작성한 항목 수정·삭제      | 가능          | 가능          | 불가능                      |
| 다른 사람이 작성한 항목 수정·삭제 | 가능          | 불가능        | 불가능                      |
| 완료 체크                         | 가능          | 불가능        | 불가능                      |
| 작성자 승인·권한 해제             | 가능          | 불가능        | 불가능                      |

로그인한 사람은 자신의 별도 공간을 만들 수 있습니다. 이것이 다른 사람의 공간에 접근 권한을 주지는 않습니다.

개인 모드와 공유 모드의 기록은 분리됩니다. 계정에 로그인해도 기존 개인 기록을 자동 업로드하지 않으며, 로그아웃하면 해당 브라우저의 개인 기록으로 돌아옵니다. 현재 버전에서 백업 파일 불러오기는 개인 모드에서만 제공됩니다.

Supabase 실제 프로젝트가 아직 없으므로 실제 이메일 전송과 원격 저장은 연결 후 확인해야 합니다. SQL 권한은 로컬 PostgreSQL 엔진(PGlite)으로 검사했습니다.

## 디자인 배경

참고 이미지의 UI를 실제 HTML 요소로 다시 만들고, 배경에서는 UI를 제거했습니다. 배경 생성 방식과 최종 프롬프트는 [이미지 제작 기록](design/ASSETS.md)에 보관했습니다. 자체 호스팅하는 글꼴과 아이콘에는 해당 npm 패키지의 라이선스가 적용됩니다.
